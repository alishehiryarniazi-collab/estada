# Estada — Project Notes (live build log)

Internal working notes so any new session has instant context without re-explaining. Keep this updated as the project evolves.

## Purpose
Real estate listing platform for the Pakistani market. Dealers/owners list properties; buyers search, filter, shortlist, and contact via in-app chat. Trust & verification (CNIC identity, document verification badge, fraud reporting) are core, not afterthoughts.

## Tech decisions (and WHY)
- **Maps: Leaflet + OpenStreetMap + Nominatim**, NOT Google Maps. Google requires a credit card even on the free tier, which breaks the "free/no-card only" rule. Data model stores plain lat/lng so a future swap to Google is a component change only.
- **Images: Cloudinary free tier** (no credit card). Handles upload + compression + CDN.
- **DB: MySQL 8 + Prisma** (Ali's choice — he has MySQL 8.0 running locally on :3306; free, no card, unblocks live dev immediately). Spec said Postgres, but MySQL is fully fine here. MySQL-specific adaptations made: long fields use `@db.Text`/`@db.VarChar(500)` (MySQL defaults String→VARCHAR(191)); removed Postgres-only `mode:'insensitive'` in search (MySQL default collation is already case-insensitive). Full schema (incl. all Phase-2 tables) built from day one to avoid painful migrations later. `DATABASE_URL=mysql://root:PASSWORD@localhost:3306/estada`.
- **Auth: JWT in httpOnly cookies + bcrypt.** Google OAuth added in a later milestone; email/password first so nothing is blocked.
- **Money format:** one reusable PKR lakh/crore utility (built in Milestone 1) — never repeat the logic per component.

## Key rules baked into the design (don't violate)
- Only ONE coral CTA button visible per screen.
- Green = verification/trust signals ONLY (never decorative).
- Exact address hidden publicly until an enquiry is made (show ~100m offset pin).
- Phone numbers hidden until BOTH buyer & dealer opt to share inside chat.
- Document verification workflow is built from the start (manual admin review OK).
- Homepage hero MUST use a real property photo (never a plain color/gradient).
- Logo (icon + wordmark) used in navbar, favicon, and emails — never plain text.
- Mobile-first, tested down to 360px.
- No hardcoded secrets; Maps has no key to leak (OSM). Validate every input client + server.

## Local run quirk (important)
The preview/launch tooling ignores `cwd` and `--prefix`, so the dev server was starting from the repo ROOT — which broke Tailwind config resolution AND caused a duplicate-React "Invalid hook call". FINAL FIX: root `.claude/launch.json` "estada-client" entry runs `cmd /c "cd /d estada\client && npm run dev"` so vite runs with cwd=client (like a normal `cd client && npm run dev`). Tailwind/PostCSS/Vite configs still use absolute paths (import.meta.url) + `resolve.dedupe:['react','react-dom']` as belt-and-suspenders. Client dev port = 5176, server = 5000.
